How this is scored

Headline metric = cost-per-success — total run cost divided by tasks passed. A tool that solves the same tasks at half the price wins, even at an identical pass-rate. Raw tokens_in is not comparable across tools: a multi-turn agent sums cache-inclusive prompt tokens across a whole loop, while a single-turn claude -p reports only one turn's fresh input. Cost-per-success normalizes that.

Cache-read % is shown on purpose. Prompt-caching state varies by provider routing day to day; an external cache-off day can make a cheaper change look more expensive. Compare agents at similar cache-read %, and treat fresh tokens (cache-state-independent) as the honest efficiency signal — it's what the regression gate ratchets.

Self-verifying suite. 27 tasks across Rust, Python, and Node. Each ships a frozen broken repo plus a machine oracle (cargo test / python3 -m unittest / node --test / grep); tasks 11–27 also ship a reference solution proven to pass the oracle offline, with zero model calls. Open-ended tasks are graded by a different-vendor model to avoid self-marking.

Every agent that we can drive through the same harness lands on this board automatically — additional model configs and third-party CLIs (Claude Code, Aider, Cursor) populate as head-to-head runs are published. The page renders whatever is in the data; no number here is hand-entered.

Reproduce it yourself

git clone https://github.com/e2p-ai/forge && cd forge
cargo build --release -p forge-voice
cd benchmarks
# full sweep (makes real, paid model calls):
FORGE_VOICE_BIN=$PWD/../target/release/forge-voice ./score.sh --agents forge
./lib/build-report.sh          # cost-per-success scorecard
./bench-gate.sh --agent forge  # regression gate vs baseline.json
Provenance loads with the data.
